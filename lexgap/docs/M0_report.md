## 3. M0-2 走査性能

`union-keys.txt`（499,750行）が本体レコード数と完全一致し、かつ頻度降順であることを確認した。このため走査はキー一覧を順に `GetStr` する方式を採る（ハッシュバケット走査を自前実装するより単純で、頻度順が無償で得られる）。

| 処理 | 実測 | 備考 |
|---|---|---|
| 全キー読取のみ | **12.1秒**（24 µs/キー） | JSON復号なし |
| 全件走査＋レコード復号＋分野推定 | **97秒**（194 µs/キー、5,157件/秒） | `dict-stats` |
| 先頭20,000キー（高頻度＝巨大レコード） | 19.3秒（966 µs/キー） | 先頭ほど1件が重い |

分野推定（`guess_domain`）が全走査時間の約87%を占める。標本抽出は1回限りの処理であり、プローブごとのコストではないため許容するが、`sampler` 実装時は分野推定を必要とする層（`aux_domains`）だけに限定する最適化余地がある。

**エントリ数**: キー499,750に対しエントリ501,069（1キーが複数エントリを持つ場合がある。例: `japan` → `Japan` と `japan`）。

## 4. M0-3 頻度フィールド（Q-01）— 解消

### 4.1 候補フィールドの実測被覆率

| フィールド | 出現率 | 範囲 |
|---|---|---|
| **`probability`** | **100.0%**（501,069/501,069） | 0 〜 0.625、中央値 4e-07 |
| `aoa_concept` | 13.3% | 3.27 〜 27.9 |
| `share` | 1.9% | 0.125 〜 0.953 |
| `aoa_base` | 1.1% | 5.13 〜 23.9 |

`probability` 以外は被覆率が低すぎて主特徴量にできない。

### 4.2 打ち切りの発見

`probability` は100%存在するが、**`1e-07` を報告下限とする左打ち切り**を受けている。最小の正値がちょうど `1e-07` であり、それ未満は `0` として記録される。

- `probability == 0` のエントリ: **190,234件（38.0%）**
- 正値の最小: `1e-07`

### 4.3 打ち切りの分布

打ち切りは一様ではなく、**下位30%（頻度順位）に集中**する。

| 頻度順位 | `probability == 0` の割合 |
|---|---|
| 0〜40% | 約0% |
| 40〜60% | 約0% |
| 60〜70% | 79.5% |
| 70〜80% | 100% |
| 80〜100% | 100% |

### 4.4 解消内容

`log(probability)` で20分位に分割すると、辞書の38%が最終分位に集中し `per_quantile=100` の均衡が崩れる。

**採用方針**: 分位は `union-keys.txt` の**頻度順位 `freq_rank`** で切る。キー一覧は全語を被覆し、打ち切り領域内の順序も保持する。`log_freq` は `log10(max(probability, 1e-07))` として予測器の特徴量に残す（左打ち切り値 −7.0）。

計画書が未解消時フォールバックとして挙げた外部頻度表（wordfreq等）は**不要**である。辞書内部に完全な順序情報が存在するため、外部依存を追加しない。

## 5. M0-4 例文-語義対応（Q-02）— 解消

### 5.1 実測

| 項目 | 実測 |
|---|---|
| 例文オブジェクト総数 | **1,186,371** |
| 例文に語義スコープの標識を持つもの | **0** |
| 例文を持つエントリ | 328,033（65.5%） |
| 例文オブジェクトの構造 | `{"e": 英文, "j": 和訳}` のみ |
| `item`（語義）を持つエントリ | 501,069（100%） |
| 語義総数 | 1,036,050 |
| `[translation]:` を持つ語義 | 223,665（21.6%） |

### 5.2 解消内容

例文は**エントリ単位**であり、特定の語義に紐付ける情報を持たない。

**採用方針**: 条件C4（語義単位ゲーティング）は例文→語義対応を用いない。計画書 §6 のフォールバックに従い、**スコア上位語義で代用**する。

P2 の正解肢生成（計画書 §4.4）も同様に、計画書が示した「対応不明の場合はスコア上位語義」の経路を既定とする。

### 5.3 付随して判明した制約

- **訳語を持たないエントリが14.2%**（71,176件）存在する。語義側の `[translation]:` からも回復できるのは26件のみである。
- 訳語の無い語は**正解が定義できず判定不能**であるため、プローブ対象から除外する（`require_translation = true`）。
- 高頻度層（先頭20,000キー）では訳語被覆率が99.8%であり、主要な標本層では除外の影響は小さい。

## 6. 計画書からの逸脱

| 項目 | 計画書 | 実装 | 理由 |
|---|---|---|---|
| 依存 `tkrzw>=0.1` | C++バインディングを直接使用 | **不採用**。`tkrzw-dict-agent` 経由で `pytkrzw` を使用 | 親プロジェクトがC++を排除しPure Python化済み。同一リポジトリ内で両方式を混在させない |
| 頻度の代替 | 未解消時は外部頻度表（wordfreq等） | **不要**。内部の `freq_rank` を使用 | §4.4 |
| 分位の基準 | 対数頻度 | **頻度順位 `freq_rank`** | `probability` の左打ち切りにより対数頻度では均衡が崩れるため |
| C4（語義単位） | 例文の語義対応を前提 | **スコア上位語義で代用** | §5.2 |
| 配置 | `~/lexgap` | `~/src/tkrzw_dict_agent/lexgap` | 利用者判断（親リポジトリ内サブプロジェクト） |

## 8. M0-6 スキーマ

`init-db` により10テーブルを作成（冪等、WAL有効、外部キー有効、schema v1）。

```
sample_sets, samples, models, probes, judgments, audit_tasks,
features, predictions, intervention_runs, meta
```

設計上の要点:

- `probes` の UNIQUE 制約 `(set_id, headword, model_id, task, prompt_ver)` が**キャッシュそのもの**。再実行時は挿入前 SELECT で既存を検出し、モデル呼び出しをスキップする。
- トランザクション単位は**1プローブ**。失敗時はロールバックし、部分書き込みを残さない（テストで検証済み）。
- `PRAGMA journal_mode=WAL` により、レポータ（読み）がプローブ実行（書き）をブロックしない。
